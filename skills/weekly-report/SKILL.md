# Weekly report

## Purpose

Turn a week of project activity into a short, source-backed report a person can read in a few minutes.

## Procedure

1. Read `memory/MEMORY.md` for context from earlier weeks.
2. List the week's commits and merged change requests. Group them by area.
3. For each group, write what changed, why it matters, and the next step.
4. Save the report to `reports/weekly-<date>.md`.
5. Commit and open a change request. Do not merge it.

## Rules

- One short paragraph per group. Name the files and commands involved.
- Mark anything you could not verify. Never invent a number.
- Keep the whole report under one page.

This skill ships with the open source Kortix starter, so edit it like any other file in the repo.
